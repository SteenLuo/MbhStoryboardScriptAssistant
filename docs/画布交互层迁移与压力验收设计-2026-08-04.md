# 画布交互层迁移与压力验收设计

日期：2026-08-04  
状态：已确认，待实施

## 1. 目标

把当前以大滚动容器和全量 DOM 重绘为主的画布，迁移为 React Flow 驱动的视口变换画布。目标是让完整漫剧项目的数百个节点仍可平移、缩放、拖拽、连线、编辑并可靠保存。

本次只替换画布的渲染和交互层；不改变现有画布 JSON、服务端 API、业务节点类型、生成链路、归档规则或历史数据。

## 2. 已确认的规模与验收

| 层级 | 节点 | 连线 | 必须通过的交互 |
| --- | ---: | ---: | --- |
| 日常项目 | 200 | 400 | 平移、缩放、节点拖拽连续流畅 |
| 单部漫剧 | 500 | 1,000 | 平移、拖拽、框选、定位、保存和重载稳定 |
| 压力场景 | 1,000 | 2,000 | 可打开、缩放、定位、选择、编辑和保存；无明显假死 |

验收在同一台本地开发机、同一浏览器中执行。日常项目的交互帧预算目标为 16.7ms；单部漫剧为 33ms；压力场景不得出现超过 100ms 的连续交互长任务。实际报告必须同时列出硬件、浏览器和测量结果，不能只写“流畅”。

## 3. 交互架构

### 3.1 视口和节点

- React Flow 负责全画布 `translate + scale`、滚轮缩放、平移、框选与连线手势。
- 每一个小说、剧本、分镜、图片、视频、标识和合并版本节点映射为一个 React Flow custom node。
- 节点坐标继续来自现有 `x/y/width/height`；连线继续来自现有 `edges`，因此旧画布无需迁移数据。
- 节点组件必须 memo 化；拖动一个节点不能刷新无关节点。

### 3.2 大画布策略

- 优先启用库的可见元素渲染能力，并为视口留出适量预加载边界。
- 视口外节点不创建正文 Markdown、复杂按钮、版本轨或缩略图的完整 DOM。
- 图片、视频预览延迟加载；节点在远距离缩小时只显示轻量摘要。
- 小地图使用节点数据摘要；视口变化只更新视口框，不重建全部节点 DOM。

### 3.3 保存与可靠性

- 拖动过程只维护前端瞬时位置；`pointerup` / `onNodeDragStop` 才写入当前画布状态。
- 一个拖动手势最多发起一次 `/api/canvas/save` 请求；不能在 `pointermove` 期间保存。
- 保存完成后仍沿用服务端的归档保护、生成中节点保护、分镜校验和串行 mutation 队列。

## 4. 兼容边界

必须保留：节点新建、编辑标题和正文、自动保存、节点尺寸调整、左右连接点、连线菜单、框选/分组、合并版本、分镜问题、生成中状态、缩放/定位/适配、小地图、撤销/重做、归档和回收站。

不得采用远程 CDN。所有画布依赖必须随本地客户包交付，并被打包脚本纳入验证。

## 5. 实施顺序

1. 建立最小前端构建入口，在 `app/public` 输出本地可缓存 bundle；服务器继续提供原有静态页面和 API。
2. 写数据适配层和 React Flow 画布壳，先覆盖平移、缩放、拖拽和持久化。
3. 逐项接入业务节点内容、连线、编辑、分组、合并、生成状态和历史操作。
4. 删除旧画布热路径，只保留数据/API 兼容代码；不同时维护两个可编辑画布。
5. 加入可重复生成的 200/500/1000 节点压力样本、交互计时和回归测试。
