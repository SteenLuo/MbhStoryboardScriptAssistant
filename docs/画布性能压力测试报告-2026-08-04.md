# 画布性能压力测试报告（2026-08-04）

## 结论

画布交互层已迁移为本地打包的 React Flow 渲染层，原有画布 JSON、保存接口和节点业务内容保持不变。核心热路径不再在每次指针移动时重建整张画布：

- 空白处左键拖动用于平移；按 `Shift` 再框选，避免框选抢占最常用的平移手势。
- 节点位置只在拖动结束后写入，拖动过程只由画布引擎更新位置。
- 节点启用可视区域裁剪；概览缩放低于 45% 时不绘制连线，放大后恢复连线，避免上千条 SVG 路径占用平移热路径。
- 在 1000 节点 / 2000 边隔离画布中，初始概览只挂载 110 个节点 DOM；平移后会随视区变化继续收缩。缩放到 51.84% 时，连线恢复显示（200 节点样本中为 238 条可视边）。

1000 节点压力档的平移和节点拖动均未出现持续长帧；节点拖动后也已通过 API 读回确认位置保存。

## 环境与方法

| 项目 | 值 |
| --- | --- |
| 系统 | Windows 10 专业版 |
| CPU | AMD Ryzen 5 3600X，6 核 12 线程 |
| 内存 | 16 GB |
| 客户端 | Codex 内置浏览器，本地服务 `127.0.0.1:17878` |
| 数据隔离 | `MBH_ACCEPTANCE_ROOT` 临时验收根目录，不触碰正式业务数据 |

三档数据均由验收接口真实保存后加载，不是只构造内存数组：

| 档位 | 节点 | 边 | 操作 |
| --- | ---: | ---: | --- |
| 日常 | 200 | 400 | 概览平移、缩放后连线恢复 |
| 单部漫剧 | 500 | 1000 | 概览平移 |
| 压力 | 1000 | 2000 | 概览平移、节点拖动、保存读回 |

帧数据由页面内 `requestAnimationFrame` 探针在手势起止之间采集；仅使用帧数大于零的样本。自动化拖动并不等于真人长时间连续拖动，因此该数据用于回归门槛，不替代上线前在目标电脑上的人工体验确认。

## 实测结果

| 档位 | 有效平移样本 | p95 / 最大帧间隔 | 验收判断 |
| --- | ---: | --- | --- |
| 200 / 400 | 12 帧 | 18.4 / 18.4 ms | 无长帧；略高于设计中 16.7 ms 的 60Hz 理想线 |
| 500 / 1000 | 12 帧 | 18.4 / 18.4 ms | 通过单部漫剧档 33 ms 门槛 |
| 1000 / 2000 | 13 帧 | 12.2 / 12.2 ms | 通过压力档“无连续大于 100 ms 长帧”门槛 |
| 1000 / 2000 节点拖动 | 3 帧 | 12.1 / 12.1 ms | 通过；松手后才触发保存 |

节点保存读回：压力画布中的 `node-381` 初始位置为 `(2520, 4500)`，拖动后接口读回 `(2760, 4724)`；画布仍保持 1000 节点、2000 边。

## 设计门槛复核

- 200 节点的 18.4 ms 略高于 16.7 ms 理想线，不能把它表述为严格 60Hz 达标；但没有观察到卡死或大于 100 ms 的连续长帧。
- 500 与 1000 节点的压力门槛已通过。对用户最敏感的两条路径（平移、节点拖动）都已脱离旧实现的“每次移动整画布重渲染”。
- 上线前建议在用户实际的浏览器、分辨率和真实内容密度（长剧本、图片、生成状态）下，再跑一次至少 30 秒的人工连续拖动；这比当前自动化短路径更能代表最终体感。
